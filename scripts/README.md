# Scripts 目录说明

本目录包含项目开发和维护相关的脚本文件。

## 📁 目录结构

```
scripts/
├── dev/                      # 开发环境脚本
│   ├── 快速启动.bat           # 🌐 日常开发（推荐）- 前后端同时启动
│   └── Tauri开发.bat         # 🖥️  桌面应用 - 测试原生功能
│
├── build/                    # 构建打包脚本
│   ├── 一键打包.ps1          # 📦 一键打包脚本（PowerShell版本）
│   └── 一键打包.bat          # 📦 一键打包脚本（批处理包装）
│
├── build/                    # 构建打包脚本
│   ├── 一键打包.ps1          # 📦 一键打包脚本（PowerShell版本）
│   ├── 一键打包.bat          # 📦 一键打包脚本（批处理包装）
│   └── README.md             # 构建脚本详细说明
│
├── utils/                           # 工具脚本
│   ├── clear-cache.bat              # 🧹 清理缓存和构建产物（含配置修复）
│   ├── backup-database.bat          # 💾 数据库备份工具
│   ├── health-check.bat             # 🏥 项目健康检查
│   ├── apply-indexes.bat            # 🚀 数据库索引优化（性能提升70-90%）
│   ├── remove-indexes.bat           # 🔄 移除索引（回滚优化）
│   ├── check-database-path.bat      # 🔍 数据库路径诊断（新增）
│   ├── migrate-database-to-appdata.bat # 🚚 迁移数据库到AppData（新增）
│   ├── 修复管理员密码.ps1
│   ├── 更新订单配置.ps1
│   └── sql/                         # SQL脚本
│       ├── add_order_configs.sql
│       └── reset_admin_password.sql
│
└── README.md                # 本文档
```

#### 🧹 智能缓存清理
```bash
scripts\utils\clear-cache.bat
```

**核心功能**：
- ✅ **Vite 缓存**：清理 3 个位置的 Vite 开发缓存
- ✅ **构建产物**：清理 dist、build 目录
- ✅ **Tauri 缓存**：可选清理 Rust 编译缓存（2-3GB）
- ✅ **Puppeteer 缓存**：清理浏览器缓存
- ✅ **测试产物**：清理 test-results、playwright-report、coverage
- ✅ **临时文件**：清理 .log、temp_*、系统垃圾文件
- ✅ **配置修复**：自动检查并修复配置文件路径问题

**智能特性**：
- 🎯 **交互式选择**：询问是否清理 Tauri 缓存（避免误删）
- 📊 **清理统计**：显示清理了多少项目
- 🛡️ **安全检查**：只清理可重新生成的文件
- 💡 **操作提示**：清理后的下一步建议

**适用场景**：
| 场景 | 说明 |
|------|------|
| 🔧 **项目出错** | Vite 缓存导致的奇怪错误 |
| 🚚 **迁移项目** | 复制到新电脑后路径问题 |
| 🔄 **切换分支** | 依赖更新或大版本切换 |
| 🏗️ **构建失败** | 清理旧的构建产物 |
| 🧪 **测试清理** | 清理测试报告和覆盖率数据 |

**使用示例**：
```bash
# 标准清理（保留 Tauri 缓存）
scripts\utils\clear-cache.bat
# 选择 N（默认）

# 深度清理（包含 Tauri 缓存）
scripts\utils\clear-cache.bat
# 选择 Y（首次重编译需 10-15 分钟）
```

**💡 提示**：
- 此脚本已集成配置文件修复功能
- 不会删除 node_modules（依赖包）
- 不会删除数据库文件（data/*.sqlite）

#### 🚚 数据库迁移到 AppData（新增 2026-01-18）

```bash
scripts\utils\migrate-database-to-appdata.bat
```

**功能**：
- ✅ 迁移数据库到 AppData 目录
- ✅ 自动备份现有数据库
- ✅ 显示迁移进度
- ✅ 保留原数据库文件

**使用场景**：
- 🔄 统一开发模式数据库路径
- 📦 从旧版本升级
- 🔧 解决数据不一致问题
- 🆕 首次配置开发环境

**迁移步骤**：
```
1. 检查源数据库（项目目录）
2. 创建 AppData 目录
3. 备份现有数据库（如果存在）
4. 复制数据库到 AppData
5. 验证迁移结果
```

**安全特性**：
- ✅ 迁移前显示数据库信息
- ✅ 询问是否覆盖现有数据库
- ✅ 自动创建备份
- ✅ 保留原数据库文件

**迁移后**：
- Web 开发模式（快速启动.bat）
- Tauri 开发模式（Tauri开发.bat）
- 两者使用相同的数据库

**💡 重要说明**：

从 2026-01-18 版本开始，系统已优化数据库路径管理：

| 开发模式 | 数据库路径 | 说明 |
|---------|-----------|------|
| 🌐 Web 开发 | `AppData/com.pp.ordermanagement/data/erp.sqlite` | ✅ 统一路径 |
| 🖥️ Tauri 开发 | `AppData/com.pp.ordermanagement/data/erp.sqlite` | ✅ 统一路径 |

**优势**：
- ✅ 两种模式数据一致
- ✅ 符合桌面应用规范
- ✅ 数据持久化存储
- ✅ 无需手动同步

## 🆘 常见问题

### Q1: 如何选择开发模式？

**A**: 非常简单：

| 场景 | 选择 |
|------|------|
| 日常开发（UI、API、业务） | 🌐 `快速启动.bat` |
| 测试原生功能（文件保存、托盘） | 🖥️  `Tauri开发.bat` |

**记住**: 95%的时间用 `快速启动.bat`

---

### Q2: 启动失败怎么办？

**A**: 标准排查流程：

```bash
# 步骤1: 停止所有服务（Ctrl+C）

# 步骤2: 清理缓存
scripts\utils\clear-cache.bat

# 步骤3: 重新启动
scripts\dev\快速启动.bat
```

---

### Q3: 端口被占用怎么办？

**A**: 查找并结束占用进程：

```bash
# 查找占用端口的进程
netstat -ano | findstr :5173   # 前端
netstat -ano | findstr :3000   # 后端

# 结束进程（替换 [PID] 为实际进程ID）
taskkill /F /PID [PID]
```

---

### Q4: Tauri 开发模式启动失败？

**A**: 检查 Rust 工具链：

```bash
# 检查 Rust 是否安装
cargo --version

# 如未安装，访问：https://rustup.rs
# 安装后重启终端并更新
rustup update
```

---

### Q5: 如何停止开发服务器？

**A**: 3种方法：
- **快捷键**: `Ctrl+C`（推荐）
- **关闭终端**: 直接关闭窗口
- **任务管理器**: 结束 node.exe

---

### Q6: 配置文件路径错误？

**A**: 运行 `scripts\utils\clear-cache.bat`，它会自动检查并修复配置文件路径问题

---

### Q7: 是否需要清理 Tauri 缓存？

**A**: 通常**不需要**，除非：
- Tauri 构建失败
- Rust 依赖更新
- 磁盘空间不足（可释放 2-3GB）

**⚠️ 注意**：清理后首次编译需要 10-15 分钟

---

### Q8: 清理缓存会影响数据吗？

**A**: **不会**！只清理可重新生成的文件：
- ✅ 数据库文件（data/*.sqlite）- 不会删除
- ✅ 源代码 - 不会删除
- ✅ 依赖包（node_modules）- 不会删除
- ✅ 配置文件 - 只修复，不删除

---

### Q9: 为什么两种开发模式数据不一致？

**A**: 2026-01-18 前的版本存在数据库路径不一致问题：
- 旧版 Web 模式使用：`项目目录/data/erp.sqlite`
- Tauri 模式使用：`AppData/com.pp.ordermanagement/data/erp.sqlite`

**解决方案**：
```bash
# 1. 检查当前状态
scripts\utils\check-database-path.bat

# 2. 迁移数据库（如需要）
scripts\utils\migrate-database-to-appdata.bat

# 3. 重新启动开发模式
scripts\dev\快速启动.bat
```

---

### Q10: 数据库存储在哪里？

**A**: 当前版本统一使用 AppData 目录：

**Windows**:
```
C:\Users\<用户名>\AppData\Roaming\com.pp.ordermanagement\data\erp.sqlite
```

**macOS**:
```
~/Library/Application Support/com.pp.ordermanagement/data/erp.sqlite
```

**Linux**:
```
~/.local/share/com.pp.ordermanagement/data/erp.sqlite
```

**优势**：
- ✅ 符合操作系统规范
- ✅ 数据不会因项目移动而丢失
- ✅ 两种开发模式使用相同数据库

---

### Q11: 如何查看数据库文件？

**A**: 使用任意 SQLite 客户端：

**推荐工具**：
- [DB Browser for SQLite](https://sqlitebrowser.org/)（免费、跨平台）
- [DBeaver](https://dbeaver.io/)（功能强大）
- VS Code 插件：SQLite Viewer

**快速访问**：
```bash
# Windows 打开数据库目录
explorer %APPDATA%\com.pp.ordermanagement\data

# 或使用诊断工具查看路径
scripts\utils\check-database-path.bat
```
