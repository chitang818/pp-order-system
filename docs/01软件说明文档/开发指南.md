## 模式一：⚡ 快速开发（浏览器模式）

### 启动方式
```bash
npm run dev
```

### 特点
- ✅ **启动超快**：2-5秒即可开始开发
- ✅ **热更新**：修改代码立即生效
- ✅ **浏览器DevTools**：强大的调试工具
- ✅ **多浏览器测试**：可在Chrome、Edge、Firefox中测试
- ❌ **功能限制**：文件保存会降级为浏览器下载（自动下载到"下载"文件夹）

### 适用场景
```
✅ 最适合：
  • 修改 UI 样式（颜色、布局、字体、间距）
  • 调整页面布局和响应式设计
  • 开发和调试表单验证逻辑
  • 修复计算错误和业务逻辑
  • 优化交互动画和用户体验
  • 调整表格、图表显示效果
  • CSS/HTML 的快速迭代
  
❌ 不适合：
  • 测试文件保存对话框
  • 测试托盘图标、开机自启等原生功能
```

### 工作原理
```
┌─────────────────┐
│  浏览器窗口     │  ← 在 Chrome/Edge 中打开
│  localhost:5173 │
└────────┬────────┘
         │ HTTP请求 /api/*
         ▼
    ┌──────────┐
    │ 后端API  │  ← 需手动启动 (npm run dev:backend)
    │ :3000    │     或自动启动 (npm run dev:all)
    └──────────┘
```

### 使用建议
**推荐时间占比：75%**

这是日常开发的首选模式！大部分前端开发工作都可以在这个模式下完成。

---

## 模式二：🌐 全栈开发（浏览器+后端）

### 启动方式
```bash
npm run dev:all
```

### 特点
- ✅ **自动启动**：同时启动前端和后端
- ✅ **完整API**：可以正常调用后端接口
- ✅ **等待机制**：前端会等待后端启动完成
- ✅ **彩色日志**：前后端日志分别显示，易于区分
- ❌ **功能限制**：同"快速开发"模式，文件保存降级

### 适用场景
```
✅ 最适合：
  • 前后端联调
  • API 接口对接和测试
  • 数据库操作功能开发
  • 业务逻辑完整测试
  
❌ 不适合：
  • 纯UI调整（用"快速开发"更快）
  • 原生功能测试（用"桌面应用"模式）
```

### 工作原理
```
终端窗口显示：
┌─────────────────────────────────┐
│ [backend]  ✓ 后端启动成功 :3000 │ ← 蓝色
│ [frontend] ✓ 前端启动成功 :5173 │ ← 绿色
│ [backend]  接收到 API 请求...    │
│ [frontend] 页面热更新...         │
└─────────────────────────────────┘
```

### 使用建议
**推荐时间占比：20%**

需要测试完整业务流程时使用。如果只是改样式，用"快速开发"模式更快。

## 模式三：🖥️ 桌面应用开发（Tauri模式）

### 启动方式
```bash
npm run tauri:dev
```

### 特点
- ✅ **完整功能**：所有原生功能都可用
- ✅ **真实环境**：与打包后的应用完全一致
- ✅ **系统原生**：文件对话框、托盘图标、开机自启等
- ⚠️ **启动较慢**：首次15-30秒（Rust编译），后续5-10秒
- ⚠️ **Rust环境**：需要安装Rust工具链

### 适用场景
```
✅ 必须使用：
  • 开发/测试文件保存功能（系统原生"另存为"对话框）
  • 开发/测试文件打开功能（系统文件选择器）
  • 测试托盘图标功能（系统托盘右下角）
  • 测试开机自启动功能
  • 测试窗口管理（最小化、最大化、隐藏）
  • 测试单实例限制（只能打开一个窗口）
  • 修改了 Rust 代码 (src-tauri/*)
  • 添加了新的 Tauri 插件
  • 发布前完整功能验证
  
❌ 不必使用：
  • 修改样式、布局（用"快速开发"模式）
  • 调试前端逻辑（用"快速开发"模式）
  • API对接（用"全栈开发"模式）
```

### 工作原理
```
┌──────────────────────────────┐
│  Tauri 桌面应用窗口          │  ← 原生窗口，非浏览器
│  (内嵌 WebView)              │
├──────────────────────────────┤
│  ✅ Rust 后端（系统原生能力）│
│  ✅ 文件系统访问             │
│  ✅ 系统对话框               │
│  ✅ 托盘图标                 │
│  ✅ 窗口控制                 │
└──────────────────────────────┘
         │ 加载前端
         ▼
    Vite Dev Server
    (localhost:5173)
```

### 系统原生功能说明

#### 什么是"系统原生功能"？
就是**普通桌面软件能做的事情**，浏览器做不到的功能。

**示例对比：**

| 功能 | 浏览器 | Tauri桌面应用 |
|------|--------|--------------|
| 文件保存 | ❌ 只能自动下载到"下载"文件夹 | ✅ 弹出"另存为"对话框，用户选择位置 |
| 文件打开 | ❌ 只能用 `<input type="file">` | ✅ 系统原生文件选择器 |
| 托盘图标 | ❌ 不可能 | ✅ 任务栏右下角图标（如QQ、微信） |
| 关闭窗口 | ❌ 关闭标签页=退出 | ✅ 关闭窗口=最小化到托盘，不退出 |
| 开机自启 | ❌ 不可能 | ✅ 可以设置开机自动启动 |
| 多实例 | ❌ 可以打开10个标签页 | ✅ 单实例（只能运行一个窗口） |

**代码示例：**

浏览器环境（自动降级）：
```javascript
// ❌ 文件自动下载到 C:\Users\用户名\Downloads\
const link = document.createElement('a');
link.download = '订单.xlsx';
link.click();
```

Tauri环境（完整功能）：
```javascript
// ✅ 弹出Windows原生对话框，用户选择保存位置
import { save } from '@tauri-apps/plugin-dialog';
const filePath = await save({
  defaultPath: '订单.xlsx',
  filters: [{ name: 'Excel', extensions: ['xlsx'] }]
});
// 用户可以保存到任意位置：D:\我的文档\客户\2026\订单.xlsx
```

### 使用建议
**推荐时间占比：5%**

只在**必要时**使用！大部分开发工作不需要这个模式。

## 🎯 实际开发流程示例

### 场景1：修改订单列表的样式
```bash
# 第1步：启动快速开发
npm run dev

# 第2步：在浏览器中打开 http://localhost:5173

# 第3步：修改 frontend/src/pages/order/order-list-page.js
#        或 frontend/src/styles/*.css

# 第4步：保存文件，浏览器自动刷新

# ✅ 完成！不需要启动Tauri
```

**推荐理由**：
- 启动快（2秒）
- 热更新快（<1秒）
- 浏览器DevTools好用
- 不需要后端

### 场景2：开发订单导出功能
```bash
# 第1步：启动全栈开发（需要后端API）
npm run dev:all

# 第2步：开发导出逻辑
#   修改 frontend/src/services/export-service.js
#   修改 backend/services/OrderService.js

# 第3步：在浏览器中测试
#   ⚠️ 注意：文件会自动下载到"下载"文件夹

# 第4步：测试完整的文件保存功能（需要系统原生对话框）
#   停止当前开发
#   启动 Tauri 模式
npm run tauri:dev

# 第5步：在桌面应用窗口中测试
#   ✅ 可以选择保存位置
#   ✅ 完整的文件对话框体验

# ✅ 完成！
```

### 场景3：添加托盘图标功能
```bash
# 第1步：必须使用 Tauri 模式
npm run tauri:dev

# 第2步：修改 Rust 代码
#   编辑 src-tauri/src/main.rs
#   添加托盘图标逻辑

# 第3步：保存后，Tauri会自动重新编译
#   ⏳ 等待10-30秒重新编译

# 第4步：在桌面应用中查看托盘图标
#   ✅ 任务栏右下角出现图标

# ✅ 完成！
```

## 🔧 自动降级机制

本项目的前端代码**已经实现了智能降级**，可以根据运行环境自动切换功能：

### 文件保存功能
```javascript
// frontend/src/utils/file-save-helper.js
export async function saveFile(blob, defaultFileName) {
  try {
    // ✅ 尝试使用 Tauri 文件对话框
    const filePath = await save({ defaultPath: defaultFileName });
    await writeFile(filePath, data);
    return filePath;
  } catch (error) {
    // ❌ Tauri不可用，自动降级到浏览器下载
    const link = document.createElement('a');
    link.download = defaultFileName;
    link.click();
    return null;
  }
}
```

### API调用
```javascript
// frontend/src/core/api-client.js
async function apiCall(command, params) {
  if (window.__TAURI__) {
    // ✅ Tauri环境：调用 Rust Command
    return await invoke(command, params);
  } else {
    // ❌ 浏览器环境：降级到 HTTP API
    return await fetch(`/api/${command}`, {
      method: 'POST',
      body: JSON.stringify(params)
    });
  }
}
```

这意味着：
- ✅ 大部分功能在浏览器中**可以正常工作**
- ✅ 只有原生功能（文件对话框、托盘图标等）会降级
- ✅ 开发者无需担心环境差异，代码会自动适配

## 🚨 注意事项

### 1. 发布前必须完整测试
```bash
# ⚠️ 重要：发布前必须在 Tauri 模式下完整测试所有功能
npm run tauri:dev

# 测试清单：
# ✅ 文件保存对话框是否正常
# ✅ 文件打开对话框是否正常
# ✅ 托盘图标是否显示
# ✅ 开机自启是否可用
# ✅ 窗口最小化/关闭行为是否正确
```

### 2. 不同模式的端口
- 快速开发：`localhost:5173` （Vite）
- 全栈开发：`localhost:5173` （前端）+ `localhost:3000` （后端）
- Tauri开发：`localhost:5173` （Vite，由Tauri加载）

### 3. 环境变量
项目会根据运行环境自动设置：
```javascript
// 浏览器环境
window.__TAURI__ === undefined  // 浏览器模式
window.location.hostname === 'localhost'

// Tauri环境
window.__TAURI__ !== undefined  // Tauri模式
```

### 4. 后端启动
- `npm run dev`：**不会**启动后端，需要手动启动或调用mock数据
- `npm run dev:all`：**自动**启动后端
- `npm run tauri:dev`：**自动**启动后端

## 💡 常见问题

### Q1: 我该用哪个模式？
**答**：
- 改UI、样式？→ `npm run dev`
- 调API？→ `npm run dev:all`
- 测试文件保存、托盘图标？→ `npm run tauri:dev`

### Q2: 为什么Tauri模式启动这么慢？
**答**：Tauri使用Rust编写，需要编译。首次启动15-30秒，后续增量编译5-10秒。这是正常的。

### Q3: 浏览器模式能测试所有功能吗？
**答**：不能。以下功能只能在Tauri模式下测试：
- 文件保存对话框（浏览器会降级为下载）
- 托盘图标
- 开机自启
- 窗口控制

### Q4: 我修改了文件保存逻辑，需要用Tauri测试吗？
**答**：是的！必须用 `npm run tauri:dev` 测试，确保文件对话框正常工作。

### Q5: 可以同时运行多个开发模式吗？
**答**：不建议。它们会占用相同的端口。如果需要，可以修改端口配置。

## 🆘 遇到问题？

1. **启动失败**：检查是否安装了Node.js和依赖 (`npm install`)
2. **端口被占用**：关闭其他占用5173或3000端口的程序
3. **Tauri启动失败**：确保安装了Rust工具链
4. **热更新不工作**：尝试重启开发服务器
