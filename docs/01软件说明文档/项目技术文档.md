## 1. 项目概述

### 1.1 项目简介

PP外贸订单管理系统是一款基于Tauri框架开发的桌面应用，专为中小型贸易企业设计。系统采用Rust + Node.js混合后端架构，提供完整的订单管理、客户管理、产品管理和单据导出功能。

### 1.2 核心特性

- ✅ **桌面应用**: 基于Tauri框架，提供原生桌面体验
- ✅ **客户管理**: 客户信息维护、交易记录查询
- ✅ **订单管理**: 订单创建、编辑、状态跟踪、智能计算
- ✅ **产品库管理**: 产品信息同步、重量管理、型号智能提示
- ✅ **单据导出**: 支持商业发票、装箱单、销售确认书、生产通知单的PDF/Word/Excel导出
- ✅ **文档中心**: 可视化模板编辑器，支持自定义单据模板
- ✅ **数据分析**: 仪表盘统计、趋势分析、客户排行等功能
- ✅ **用户认证**: 基于会话的认证机制，支持权限管理
- ✅ **数据管理**: 本地SQLite数据库，支持自动备份和恢复
- ✅ **系统托盘**: 支持系统托盘运行，后台自动备份

### 1.3 技术特点

- **桌面应用架构**: Tauri框架，Rust后端 + Web前端
- **混合后端**: Rust处理数据库和系统操作，Node.js处理复杂导出功能
- **前后端分离**: 前端使用原生ES6模块 + Vite构建
- **模块化架构**: 路由→服务→数据访问层三层架构，代码组织清晰
- **现代化构建**: Vite构建工具，支持代码分割、Tree Shaking、热更新
- **安全机制**: HttpOnly Cookie认证、CSRF防护、输入验证
- **自动备份**: Rust实现的定时备份机制，支持后台静默执行

### 3.2 架构层次

#### 3.2.1 前端架构

**多页面应用 (MPA) + 单页面应用 (SPA) 混合模式**

- **入口页面**: `index.html` (主应用), `docs.html` (文档中心), `login.html` (登录页)
- **页面脚本**: 每个页面有独立的入口脚本，按需加载业务逻辑
- **共享模块**: API层、工具函数、组件通过ES6模块导入共享
- **Tauri集成**: 通过 `@tauri-apps/api` 调用Rust后端命令

**模块组织**:
```
frontend/src/
├── core/              # 核心模块
│   ├── app.js        # 应用初始化
│   ├── router.js     # 路由构建与映射
│   ├── state-manager.js # 状态管理
│   ├── api-client.js  # API客户端（Tauri/HTTP统一接口）
│   └── ipc-client.js  # IPC客户端（Tauri命令调用）
├── pages/             # 页面级业务逻辑
├── views/             # 视图层（MVVM模式）
│   ├── home/         # 首页视图
│   ├── orders/        # 订单视图
│   ├── customers/     # 客户视图
│   ├── analytics/     # 数据分析视图
│   └── settings/      # 设置视图
├── components/        # 可复用组件
├── services/          # 服务层
│   ├── order-service.js
│   ├── customer-service.js
│   ├── dashboard-service.js

├── api/               # API客户端与缓存
├── utils/             # 工具函数
├── config/            # 配置
└── assets/            # 静态资源
```

#### 3.2.2 Rust后端架构（Tauri Commands）

**命令式架构: Commands → DB → Models**

1. **命令层 (Commands)**
   - 职责: 接收前端调用、参数验证、调用数据层
   - 位置: `src-tauri/src/commands/*.rs`
   - 模块: `auth`, `orders`, `customers`, `products`, `users`, `database`, `dashboard`, `document_center`
   - 特点: 通过 `#[tauri::command]` 宏暴露给前端

2. **数据访问层 (DB)**
   - 职责: 数据库操作、SQL执行、连接池管理
   - 位置: `src-tauri/src/db/*.rs`
   - 特点: 使用 `rusqlite` + `r2d2` 连接池，提供线程安全的数据库访问

3. **模型层 (Models)**
   - 职责: 数据结构定义、序列化/反序列化
   - 位置: `src-tauri/src/models/*.rs`
   - 特点: 使用 `serde` 进行序列化，与前端JSON交互

4. **工具层 (Utils)**
   - 职责: 文件系统、路径管理、加密、日志
   - 位置: `src-tauri/src/utils/*.rs`
   - 特点: 封装系统级操作

#### 3.2.3 Node.js后端架构

**三层架构: 路由层 → 服务层 → 数据访问层**

1. **路由层 (Routes)**
   - 职责: 接收HTTP请求、参数解析、响应构造
   - 位置: `backend/routes/*.js`
   - 特点: 不包含业务逻辑，只负责HTTP层面处理

2. **服务层 (Services)**
   - 职责: 业务逻辑封装、数据校验、业务规则处理
   - 位置: `backend/services/*.js`
   - 特点: 可复用的业务逻辑，便于测试和维护
   - 主要服务: PDF导出、Word导出、Excel导出、模板渲染

3. **数据访问层 (DB)**
   - 职责: 数据库操作、SQL执行、数据映射
   - 位置: `backend/db/*.js`
   - 特点: 封装SQL细节，提供统一的数据库接口
   - **注意**: 在Tauri模式下，数据库操作由Rust后端处理，Node.js后端主要用于导出功能

4. **中间件层 (Middleware)**
   - 职责: 认证、授权、验证、错误处理、CSRF防护
   - 位置: `backend/middleware/*.js`
   - 特点: 横切关注点，可插拔式设计

### 3.4 路由系统

**核心文件**: `frontend/src/core/router.js`

- 负责路由解析与映射，构建视图路径（如 `orders/list`、`products/add`）
- 使用路由映射表提升性能与一致性
- 支持基础路由与子路由，提供 `fullPath` 与 `query` 信息

**映射示例片段**：

```
orders:
- list -> orders/list
- edit -> orders/edit
- default -> orders/list
- defaultHash -> #/orders/list

products:
- add -> products/add
- list -> products/list
- default -> products/list
- defaultHash -> #/products/list

settings:
- default -> settings/company
- defaultHash -> #/settings/company
- subRoutes -> true  （支持所有子路由，如 settings/users、settings/database）

customers:
- edit -> customers/edit
- default -> customers

document-center:
- generate -> document-center/generate
- templates -> document-center/templates
- templates/edit -> document-center/template-editor
```

**默认子路由与哈希映射说明**：
- 默认子路由通过 `default` 指向模块内的默认视图；哈希默认值通过 `defaultHash` 指向对应的 `#/module/sub`。
- 当未指定子路由时，路由系统会跳转到该模块的默认视图（例如 `#/orders` 将跳到 `#/orders/list`）。

**默认子路由与默认哈希速查表**

| 模块 | 默认子路由 | defaultHash |
|------|------------|-------------|
| orders | list | `#/orders/list` |
| products | list | `#/products/list` |
| settings | company | `#/settings/company` |
| customers | （无） | （未定义） |
| document-center | （无） | （未定义） |

```javascript
export async function guard(requiredRole) {

  if (!ok) {

    return false;
```

```javascript
// backend/services/PdfExportService.js
static async htmlToPdf(html, options = {}) {
  const browser = await puppeteer.launch({
    headless: 'new',
    args: ['--no-sandbox', '--disable-setuid-sandbox']
  });
  
  const page = await browser.newPage();
  await page.setContent(html, {
    waitUntil: 'domcontentloaded'
  });
  
  const pdfBuffer = await page.pdf({
    format: 'A4',
    printBackground: true,
    margin: { top: '0mm', right: '0mm', bottom: '0mm', left: '0mm' }
  });
  
  await browser.close();
  return pdfBuffer;
}
```

### 5.5 计算逻辑

#### 5.5.1 重量计算

**预估重量**:
```javascript
预估总净重 = 产品数量 × 单件预估重量
```

**净重 (NET WEIGHT)**:
```javascript
净重 = 实际重量 × 数量
// 只使用实际重量，如果实际重量为空则显示为空
```

**皮重 (TARE WEIGHT)**:
```javascript
if (件数单位 === '件') {
  皮重 = 0.25 × 件数数量
} else if (件数单位 === '托盘') {
  皮重 = 15 × 件数数量
} else if (件数单位 === '捆包') {
  皮重 = 10 × 件数数量
} else {
  皮重 = 0
}
```

**毛重 (GROSS WEIGHT)**:
```javascript
毛重 = 净重 + 皮重
// 只有净重存在时才计算毛重
```

#### 5.5.2 金额计算

**产品金额**:
```javascript
产品金额 = 数量 × 单价
```

**订单总金额**:
```javascript
// 优先级1: 使用订单表中的 totalUSD 字段
// 优先级2: 计算所有订单项金额之和
订单总金额 = Σ(产品数量 × 产品单价)
```

#### 5.5.3 包装计算

**包装数量**:
```javascript
包装数量 = 数量 ÷ 件数
// 精度处理: Math.round(计算结果 × 100) ÷ 100
```

**包装显示格式**:
- 装箱单: `{包装数量}条/{单位}` (如: `160条/托`)
- 商业发票: `{包装数量}PCS/{包装单位}` (如: `160PCS/PALLET`)

#### 5.7.2 后端ETag缓存

**实现位置**: `backend/utils/etag.js`

**工作原理**:
1. 生成数据内容的SHA-1哈希作为ETag
2. 客户端请求时携带 `If-None-Match` 头
3. 服务器比较ETag，如果匹配返回304 Not Modified
4. 如果不匹配返回新数据和新的ETag

**使用示例**:
```javascript
// 产品列表接口
app.get('/api/products', async (req, res) => {
  const products = await ProductService.list();
  const etag = generateETag(JSON.stringify(products));
  
  if (req.headers['if-none-match'] === etag) {
    return res.status(304).end();
  }
  
  res.setHeader('ETag', etag);
  res.json({ success: true, data: products });
});
```

### 7.2 CSRF防护

#### 7.2.1 双重提交Cookie模式

**实现原理**:
1. 服务器在用户认证后设置 `csrf_token` Cookie
2. 前端在写操作请求中携带 `x-csrf-token` 头
3. 服务器验证Cookie和Header中的token是否一致

**实现代码**:
```javascript
// 后端中间件
function protectIfAuthenticated(req, res, next) {
  if (req.method === 'GET' || req.method === 'HEAD') {
    return next();
  }
  
  if (!req.user) {
    return next(); // 未认证用户跳过
  }
  
  const cookieToken = req.cookies.csrf_token;
  const headerToken = req.headers['x-csrf-token'];
  
  if (!cookieToken || cookieToken !== headerToken) {
    return res.status(403).json({
      success: false,
      error: 'CSRF_TOKEN_MISMATCH',
      message: 'CSRF token验证失败'
    });
  }
  
  next();
}
```

**前端实现**:
```javascript
// frontend/src/api/api.js
function json(url, opts) {
  const method = ((opts && opts.method) || 'GET').toUpperCase();
  const headers = Object.assign({}, (opts && opts.headers) || {});
  
  if (method !== 'GET' && method !== 'HEAD') {
    const csrf = getCookie('csrf_token');
    if (csrf) headers['x-csrf-token'] = csrf;
  }
  
  // 发送请求...
}
```
